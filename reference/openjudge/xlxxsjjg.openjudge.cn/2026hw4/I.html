什么？我的 OpenJudge 怎么变得不一样了？！

其实这就是 CSS (Cascading Style Sheets) 的功劳，它可以修改网页的外观样式。由于 OpenJudge 题目没有防代码转译，在本题的“提示”部分实际上隐藏着大段的 CSS 代码，正是它们改变了这个页面的外观。

在一个 HTML 页面中，所有的元素按照嵌套关系组成了一种树形结构，称为 DOM 树。记根结点为 1 号结点，每个结点表示一个 HTML 元素，并包含：

  1. 一个标签名 tag，例如 div、span、section
  2. 一个类名 class，例如 main、item、title

为简化题目，每个结点最多只有一个类名。如果该结点没有类名，则记为 -。每个节点都有几个子节点，如此得到一个可以被浏览器识别的网页结构。

CSS 的样式是按照一个叫做“选择器”的规则来匹配 HTML 元素的。我们考虑的选择器由若干段用 > 连接而成，每一段内可能用 . 分隔，例如：

div.main>span.item>a

它表示：

  1. 找到一个标签名为 div、类名为 main 的元素
  2. 它有一个直接子元素，标签名为 span、类名为 item
  3. 这个 span 又有一个直接子元素，标签名为 a

每一段选择器支持以下三种形式：

  1. tag：例如 div，表示只要求标签名匹配
  2. .class：例如 .main，表示只要求类名匹配
  3. tag.class：例如 div.main，表示标签名和类名都必须匹配

一个结点 u 被认为匹配整个选择器，当且仅当 u 本身匹配选择器的第一段，并且可以沿着寻找若干次直接子结点的关系，依次匹配后面的所有段

一般来说，选择器会返回文档顺序下第一个匹配的结点。本题中顺序定义为从根结点开始，按照子结点给出的顺序进行深度优先先序遍历。请输出这个简化版选择器选中的结点编号；如果不存在匹配结点，输出 -1。

输入
第一行输入两个整数 N, K，分别表示结点个数与选择器中的段数。
第二行输入一个字符串，表示选择器。保证它恰好由 K 段选择器用 > 连接而成。
接下来 N 行，第 i 行描述第 i 个结点，格式为：
tag class c v1 v2 ... vc

其中：
  • tag 表示该结点的标签名
  • class 表示该结点的类名；若没有类名，则为 -
  • c 表示它的直接子结点个数
  • v1, v2, ..., vc 按从左到右的顺序给出它的所有直接子结点编号

输入保证这些结点恰好构成一棵以 1 为根的树。
输出
输出一个整数，表示被选中的结点编号；若不存在，输出 -1
样例输入
9 3
div.main>span.item>a.link
html - 2 2 3
body page 2 4 5
footer foot 0
div main 1 6
div box 2 7 8
span item 1 9
p text 0
span note 0
a link 0
样例输出
4
提示
翻译成 HTML 代码如下：
<html> <!-- 1 -->
   <body class="page"> <!-- 2 -->
      <div class="main"> <!-- 4 -->
         <span class="item"> <!-- 6 -->
            <a class="link"></a> <!-- 9 -->
         </span>
      </div>
      <div class="box"> <!-- 5 -->
         <p class="text"></p> <!-- 7 -->
         <span class="note"></span> <!-- 8 -->
      </div>
   </body>
   <footer class="foot"></footer> <!-- 3 -->
</html>

按文档顺序遍历结点的顺序为：
1, 2, 4, 6, 9, 5, 7, 8, 3

其中 4 号结点为 div.main，它的直接子结点 6 为 span.item，6 的直接子结点
9 为 a.link，因此 4 号结点匹配该选择器。

1 ≤ K ≤ N ≤ 100000, 所有标签名和类名均只包含小写英文字母，且长度不超过 10。
